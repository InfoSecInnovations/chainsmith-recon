BUGS / ISSUES TO FIX FIRST
===========================================================

- [OPEN, decision needed] Concurrent scans can still be created with the wrong
  scope. See audit F-3.
    Fix (1) landed 2026-09-10: run_scan() reads scope from the ScanSession, not
    the global AppState; DB scan row, proof_settings copy, and the compliance
    report are all scan-scoped now. Tests in
    tests/scanning/test_scan_scope_isolation.py.
    Fix (2) NOT done: scope must move inline onto POST /api/v1/scan and
    POST /api/v1/scope must go (concurrent-scans-design.md §5). Until then the
    CLI's two-step set_scope-then-scan flow can create a mis-scoped session at
    request time.
    INTERIM MITIGATION: set max_concurrent_scans: 1 (currently defaults to 4).
    OPERATOR DECISION PENDING: apply the mitigation, or accept the residual.

- [OPEN] Compliance statistics still aggregate across concurrent scans.
    violation_logger / traffic_logger are process singletons writing one
    violations_log.jsonl / traffic_log.jsonl with no scan_id per record. The
    scope half of the compliance report is correct as of fix (1); the counts are
    not. Tracked in phase57-evidence-and-capture.md 57.2.

- [OPEN] 56.17 WebUI param editing never got an operator live-smoke.
    JS was syntax-checked only. Detail modal, preset selector, include_disabled
    toggle, save-as-default.

- [OPEN, decision needed] ~36 checks can still mint duplicate observation ids.
    Found 2026-09-15 by an audit after the fakobanko duplicate-id bug (below,
    FIXED). None fires on live fakobanko. Shapes: (A) one candidate per endpoint
    with a discriminator that does not name the endpoint; (B) one grade() call
    emitting two verdicts with the same discriminator. Affected: every
    per-chat-endpoint ai_* check (e.g. ai_prompt_leakage always uses
    `prompt-leaked`; fires when a host has >=2 chat endpoints — the
    llm_endpoint_fakobanko.yaml simulation does this), ai_embedding_extraction,
    cag_cache_probe / cache_key_reverse / cache_poisoning / cross_user_leakage /
    injection_persistence / stale_context / serialization / discovery,
    agent_callback_injection / tool_abuse / streaming_injection /
    state_manipulation, web_debug_endpoints, web_redirect_chain, web_sri,
    web_mass_assignment (schema-leak), network_dns_records (TXT),
    network_reverse_dns. Also: the same hostname on two ports collides, because
    Service.host carries no port.
    Damage is now bounded: ObservationWriter keeps only the colliding row out of
    the database (logged, scanner warns) instead of dropping the rest of the scan.
    OPERATOR DECISION: (1) one guard in the grading stage that gives colliding
    ids a stable suffix and warns [recommended], (2) per-check fixes like the
    three already done, or (3) rely on the writer.

- [OPEN] ServiceIteratingCheck.run drops list outputs from all but the last
  service. app/checks/base.py:694 does `result.outputs.update(...)`, so
  chat_endpoints, rag_endpoints, cag_endpoints and mcp_servers keep only the
  last service's list; downstream checks never see the others. Confirmed by
  reading the code 2026-09-15; not yet reproduced in a scan.

- [OPEN] web_favicon grader crashes on non-latin-1 bodies.
    `_md5_of` does `body.encode("latin-1")`; fakobanko pages carry emoji, so 4
    observations per full scan are `grading_failed`, at scan time and on re-grade.
    Small fix.

- [OPEN] `chainsmith.sh start` exits 1 after `up` for every non-ollama profile.
    The trailing `[ ... = "ollama" ] && pull_ollama_model` is false under
    `set -e`; the container starts but the health wait never runs.

- phase57-evidence-and-capture.md
    57.1a, 57.1b, 57.2, 57.3, 57.4 DONE (doc §0 is the live status). All 133
    checks split into probe/grade; `dev regrade` built; superseded rows handled;
    D-21 measured (~9.7 MB per full fakobanko scan). Capture is still OFF by
    default. O-3 is resolved as sequencing: encryption is 57.5 (below).

    Decisions needed:
    - Duplicate-id exposure in ~36 checks: grading-stage guard, per-check fixes,
      or rely on the writer. (See BUGS.)
    - Hash mismatches that make three checks unreproducible from the corpus:
        rag_corpus_poisoning (14 of 70 exchanges) and rag_multimodal_injection
        (4 of 6): the http interceptor records a bytes body as `str(data)` —
        literally "b'--…'" — while the check's in-memory copy holds decoded
        text and omits the multipart Content-Type header. Proposed fix
        (mechanical, ready): one shared bytes-decoding rule for the interceptor
        and exchange_from_response, and pass the headers actually sent. Stored
        bodies become readable; old corpora keep the repr text.
        web_mass_assignment (30 of 30): the in-memory exchange carries an
        `x-chainsmith-injected-field` header that is never sent, and grade()
        depends on it, so a corpus copy would grade to zero attempts.
          A [recommended]: drop the fake header; read the injected field back
            from the recorded body (always the last key the probe adds).
          B: actually send the header (the target sees a Chainsmith-named
            header).
    - Criterion 6: accept "holds with --capture-failures" as closed, or wait
      for a pair that includes a transient failure.

    To do:
    - Fix the hash mismatches (after the decision above) and the web_favicon
      grader crash (see BUGS). These decide which checks can be re-graded.
    - Write the 2026-09-15 results into doc §0.22 (addendum) and §10.
    - Retention: designed, not implemented. EvidenceStore.delete_scan and
      EvidenceRepository.delete_scan exist; nothing schedules them. Capture
      stays off by default until this lands (operator decision, D-21).
    - Criterion 7 unverified: no scan has recorded an `llm` exchange Chainsmith
      itself made, so an agent verdict has not been traced to its prompt and
      completion from the workspace.
    - Grading records do not save check config, so a re-grade uses today's
      config values rather than the scan's.
    - Exchange documents are still written with indent=2; compacting them is the
      next size saving (not measured).
    - mcp_sampling_abuse: 1 of 2 exchanges not in the corpus. Not investigated.
      (mcp_server_fingerprint's `local` exchange and the network dns/tcp/whois
      skips are expected: those protocols are not captured by default.)
    - The scratch import's superseded-row dedupe has no test.
    - WebUI not live-smoked for superseded rows (the fix is the API default).
    - TrafficLogger.log_request has no callers.
    - docs/vocabulary.md still documents Engagement (phase-52 drift).
    - test_run_with_latency timing flake (0.0892 s against a 0.09 s floor).

    Deferred on purpose (not part of the 57.1-57.4 exit condition):
    - 57.5 evidence encryption (one key per workspace; floats, blocks nothing).
    - Criterion 3: workspace.yaml rejects `scope:`, so a workspace does not
      bound a scan's scope.
    - O-4 swarm: coordinator capture posture does not reach agents; remote

    - O-5 severity declarations for custom checks (parked).
